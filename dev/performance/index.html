Performance

All timings are wall times, best of 3, with threads pinned to cores (JULIA_EXCLUSIVE=1, OMP_PROC_BIND=close). Logs are in benchmark/results/.

Free space against Fortran

bdmk against bdmk_fortran on the same tree (Laplace kernel; Fortran built with -O3 -march=native, OpenBLAS and OpenMP). The density is $f = -\Delta u/(4\pi)$ for a sum of three Gaussians in a box of size 1.18, so the exact potential $u$ is known. Both codes reach the same error against $u$ and agree with each other to about $10^{-13}$ (benchmark/native_vs_fortran.jl).

Periodic against C++

Against the C++ periodic solver (PeriodicDMK bench_steps <cell> multi): four Gaussians down to width 0.007, norder = 16, genoa node, one socket. Both codes evaluate the same density point by point, apply the same work-saving rules and exact wide transforms, build the same forest, and agree to $2\cdot10^{-13}$ at eps = 1e-9. The last column of each group uses the SIMD.jl batch density of benchmark/periodic_vs_cpp.jl (DENSITY=simd) instead; the C++ code has no counterpart. Log: benchmark/results/periodic/genoa_simd.log.

Where the time goes (hexagonal cell, eps = 1e-9, SIMD density): at one thread, the GEMM-bound stages dominate: plane waves 0.92 s, near field 0.87 s, upward pass 0.38 s. Their kernels run at the FP64 peak. At 48 threads the plane waves (≈ 75 ms) are bound by memory bandwidth: the expansions of a level are hundreds of MB.
